# Exception Handling

## What is an Exception?

An **exception** is an event that disrupts the normal flow of a program — a runtime error. Without handling, it crashes the program. With handling, you can recover gracefully.

```java
// Without handling — program crashes:
int[] arr = {1, 2, 3};
System.out.println(arr[10]); // ArrayIndexOutOfBoundsException

// With handling — program continues:
try {
    System.out.println(arr[10]);
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Caught: " + e.getMessage());
    // program keeps running
}
```

## try / catch

Wrap **risky code** in `try`. If an exception occurs, execution jumps to the `catch` block. The `catch` block receives the exception object.

```java
public static int divide(int a, int b) {
    if (b == 0) throw new ArithmeticException("Cannot divide by zero");
    return a / b;
}

try {
    int result = divide(10, 0);
    System.out.println(result); // skipped
} catch (ArithmeticException e) {
    System.out.println("Error: " + e.getMessage()); // "Error: Cannot divide by zero"
}

System.out.println("Program continues..."); // still runs
```

**Rule:** Only put code in `try` that might throw. Keep `try` blocks small and focused.

## finally

The `finally` block **always runs** — whether an exception was thrown or not. Use it for cleanup: closing files, releasing resources, etc.

```java
public static String readData(String source) {
    Connection connection = null;
    try {
        connection = openConnection(source);
        return connection.read();
    } catch (IOException e) {
        System.out.println("Read failed: " + e.getMessage());
        return null;
    } finally {
        // This ALWAYS runs — guaranteed cleanup
        if (connection != null) connection.close();
        System.out.println("Connection closed.");
    }
}
```

`finally` runs even if the `catch` block re-throws an exception, or if there's a `return` inside `try`.

## throw

Use `throw` to **manually trigger an exception** when you detect an invalid state.

```java
public void setAge(int age) {
    if (age < 0 || age > 150) {
        throw new IllegalArgumentException("Age must be 0-150, got: " + age);
    }
    this.age = age;
}

try {
    setAge(-5);
} catch (IllegalArgumentException e) {
    System.out.println(e.getMessage()); // "Age must be 0-150, got: -5"
}
```

## throws (Checked Exceptions)

In Java, the `throws` keyword in a method signature **declares** that the method might throw a checked exception. Callers are forced by the compiler to handle it with `try/catch` or declare it themselves.

```java
// Declares that IOException might be thrown — caller must handle it
public void readFile(String path) throws IOException {
    FileReader f = new FileReader(path); // might throw IOException
}

// Caller must either catch or also declare throws
try {
    readFile("data.txt");
} catch (IOException e) {
    System.out.println("File not found: " + e.getMessage());
}
```

## Checked vs Unchecked Exceptions

Java distinguishes between two categories:

| | Checked | Unchecked |
|---|---|---|
| Compiler forces handling? | Yes | No |
| Examples | `IOException`, `SQLException` | `NullPointerException`, `ArrayIndexOutOfBoundsException` |
| Must catch or declare `throws`? | Yes | No |
| Extends | `Exception` | `RuntimeException` |
| Typical cause | External resource failure | Programming bug |

**Hierarchy:**
```
Throwable
├── Error           (JVM errors — don't catch these)
└── Exception
    ├── IOException          (checked)
    ├── SQLException         (checked)
    └── RuntimeException     (unchecked)
        ├── NullPointerException
        ├── ArrayIndexOutOfBoundsException
        └── IllegalArgumentException
```

## Custom Exceptions

Extend `RuntimeException` (unchecked) or `Exception` (checked) to create your own error types. This lets callers catch specific categories of errors.

```java
public class InsufficientFundsException extends RuntimeException {
    double amount;
    double balance;

    public InsufficientFundsException(double amount, double balance) {
        super("Cannot withdraw " + amount + ". Balance is only " + balance + ".");
        this.amount = amount;
        this.balance = balance;
    }
}

class BankAccount {
    private double balance;

    public BankAccount(double balance) { this.balance = balance; }

    public void withdraw(double amount) {
        if (amount > balance) {
            throw new InsufficientFundsException(amount, balance);
        }
        balance -= amount;
    }
}

try {
    BankAccount acct = new BankAccount(100.0);
    acct.withdraw(200.0);
} catch (InsufficientFundsException e) {
    System.out.println("Custom error caught: " + e.getMessage());
    System.out.println("Short by: " + (e.amount - e.balance));
} catch (Exception e) {
    throw e; // re-throw unexpected errors
}
```

**Best practices:**
- Include relevant context data as fields
- Catch specific types before generic `Exception`
- Re-throw errors you didn't expect
- Use `RuntimeException` for programming errors, `Exception` for recoverable conditions
