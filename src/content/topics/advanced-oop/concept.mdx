## Inheritance

**Inheritance** is a mechanism where a **child class** derives attributes and methods from a **parent class** using the `extends` keyword. The child gets everything the parent has, and can add its own on top.

```java
public class Animal {
    protected String name;

    public Animal(String name) {
        this.name = name;
    }

    public String speak() {
        return name + " makes a sound.";
    }
}

class Dog extends Animal {
    String breed;

    public Dog(String name, String breed) {
        super(name); // MUST call super() first
        this.breed = breed;
    }

    public String fetch(String item) {
        return name + " fetches the " + item + "!";
    }
}

Dog dog = new Dog("Rex", "Labrador");
dog.speak();        // inherited: "Rex makes a sound."
dog.fetch("ball");  // own method: "Rex fetches the ball!"
```

**Key rules:**
- Use `super(args)` to call the parent constructor
- A child class IS-A parent class (`Dog` IS-A `Animal`)
- A child can access all `public` and `protected` members of the parent

## protected

In Java, `protected` is an access modifier that allows:
- The class itself
- All **child classes** (subclasses)
- Classes in the **same package**

...to access a field or method, while blocking everything else.

```
Access levels (most → least restrictive):
private < (default/package) < protected < public
```

```java
public class Shape {
    protected String color; // accessible in subclasses

    public Shape(String color) {
        this.color = color;
    }
}

class Circle extends Shape {
    double radius;

    public Circle(String color, double radius) {
        super(color);
        this.radius = radius;
    }

    public String describe() {
        return "A " + color + " circle"; // can access protected field
    }
}
```

## Polymorphism

**Polymorphism** means "one interface, many forms." There are two types:

### Method Overriding (Runtime Polymorphism)
A child class provides its own implementation of a method inherited from the parent. The correct version is selected **at runtime** based on the actual object type.

```java
class Animal {
    public String speak() { return "..."; }
}

class Dog extends Animal {
    @Override
    public String speak() { return "Woof!"; }
}

class Cat extends Animal {
    @Override
    public String speak() { return "Meow!"; }
}

Animal[] animals = { new Dog(), new Cat(), new Animal() };
for (Animal a : animals) {
    System.out.println(a.speak());
}
// "Woof!"
// "Meow!"
// "..."
```

### Method Overloading (Compile-time Polymorphism)
Same method name, different parameter lists. Java supports this natively.

```java
public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }

    public int add(int a, int b, int c) {
        return a + b + c;
    }
}

Calculator calc = new Calculator();
calc.add(1, 2);     // 3
calc.add(1, 2, 3);  // 6
```

## Composition

**Composition** is a HAS-A relationship — an object **contains** another object as a field. This is an alternative to inheritance for code reuse.

```java
public class Engine {
    int horsepower;

    public Engine(int horsepower) {
        this.horsepower = horsepower;
    }

    public String start() { return "Vroom!"; }
}

class Car {
    String make;
    Engine engine; // Car HAS-A Engine

    public Car(String make, int horsepower) {
        this.make = make;
        this.engine = new Engine(horsepower);
    }

    public String start() {
        return make + ": " + engine.start();
    }
}

Car car = new Car("Toyota", 200);
car.start(); // "Toyota: Vroom!"
```

**Inheritance vs Composition:**
| | Inheritance (IS-A) | Composition (HAS-A) |
|---|---|---|
| Example | Dog IS-A Animal | Car HAS-A Engine |
| Coupling | Tight | Loose |
| Flexibility | Lower | Higher |
| Rule of thumb | Use when true IS-A exists | Prefer in most other cases |

## Abstract Class

An **abstract class** is a base class that **cannot be instantiated directly** — it exists only to be extended. It can contain `abstract` methods (declared but not implemented) that subclasses must override.

```java
public abstract class Shape {
    protected String color;

    public Shape(String color) {
        this.color = color;
    }

    // Abstract method — subclasses MUST implement
    public abstract double area();

    @Override
    public String toString() {
        return color + " shape with area " + String.format("%.2f", area());
    }
}

class Circle extends Shape {
    double radius;

    public Circle(String color, double radius) {
        super(color);
        this.radius = radius;
    }

    @Override
    public double area() {
        return Math.PI * radius * radius;
    }
}

// new Shape("red"); // ERROR — cannot instantiate abstract class
Circle c = new Circle("red", 5);
c.area(); // 78.54
```

## The Object Class

In Java, **every class implicitly extends `Object`** — it is the ultimate parent of all Java classes. This means every object automatically inherits:

- `toString()` — string representation (override this!)
- `equals(Object other)` — reference equality by default (override for value equality)
- `hashCode()` — used in HashMaps/HashSets

```java
public class Point {
    int x, y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    @Override
    public String toString() {
        return "(" + x + ", " + y + ")";
    }

    @Override
    public boolean equals(Object other) {
        if (!(other instanceof Point)) return false;
        Point p = (Point) other;
        return this.x == p.x && this.y == p.y;
    }
}

Point p1 = new Point(1, 2);
Point p2 = new Point(1, 2);
p1.equals(p2);  // true  (value equality)
p1 == p2;       // false (reference equality)
```
