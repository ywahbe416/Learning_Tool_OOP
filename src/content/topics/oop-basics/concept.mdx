# OOP in Java – Part 1

## What is Object-Oriented Programming?

OOP is a programming paradigm that organizes code around **objects** rather than functions and logic. The four pillars are: Encapsulation, Inheritance, Polymorphism, and Abstraction.

Everything in OOP starts with two fundamental concepts: **classes** and **objects**.

---

## Class

A **class** is the blueprint — it defines what attributes (data) and methods (behavior) an object will have. It does not hold data itself; it describes the shape of the data.

```java
public class Car {
    String make;
    String model;
    int year;

    public Car(String make, String model, int year) {
        this.make = make;
        this.model = model;
        this.year = year;
    }

    public String describe() {
        return year + " " + make + " " + model;
    }
}
```

Think of a class like an architectural blueprint. The blueprint isn't a house — it's the instructions for building one.

---

## Object

An **object** is a specific **instance** created from a class. You can create many objects from the same class, each with its own data.

```java
Car car1 = new Car("Toyota", "Camry", 2022);
Car car2 = new Car("Honda", "Civic", 2023);

System.out.println(car1.describe()); // "2022 Toyota Camry"
System.out.println(car2.describe()); // "2023 Honda Civic"
```

`car1` and `car2` are two separate objects — two houses built from the same blueprint.

---

## Constructor

The **constructor** is a special method that runs automatically when you create an object with `new`. Its job is to **initialize** the object's fields with starting values.

```java
public class Student {
    String name;   // instance field
    double gpa;    // instance field

    public Student(String name, double gpa) {
        this.name = name;
        this.gpa = gpa;
    }
}

Student s = new Student("Alex", 3.8);
System.out.println(s.name); // "Alex"
```

Key rules:
- The constructor always has the **same name as the class**
- It has **no return type** (not even `void`)
- If you don't define one, a default no-argument constructor is provided

## Encapsulation

**Encapsulation** means bundling data (fields) and the methods that operate on that data together inside a class — and **hiding** the internal state from the outside world.

The practice: make fields **private**, expose them only through **public getters and setters**.

```java
public class BankAccount {
    private String owner;    // private field
    private double balance;  // private field

    public BankAccount(String owner, double initialBalance) {
        this.owner = owner;
        this.balance = initialBalance;
    }

    public double getBalance() {
        return balance;
    }

    public void deposit(double amount) {
        if (amount > 0) balance += amount;
    }

    public void withdraw(double amount) {
        if (amount > balance) throw new IllegalArgumentException("Insufficient funds");
        balance -= amount;
    }
}

BankAccount acct = new BankAccount("Alice", 500.0);
acct.deposit(200.0);
System.out.println(acct.getBalance()); // 700.0
// acct.balance = 99999; // ERROR — private!
```

**Why encapsulate?**
- Protects data from being set to invalid states
- You can change the internal implementation without breaking outside code

## toString()

`toString()` is a special method that returns a **string representation** of an object. It's called automatically when you print an object with `System.out.println()`.

```java
public class Point {
    int x, y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    @Override
    public String toString() {
        return "Point(" + x + ", " + y + ")";
    }
}

Point p = new Point(3, 4);
System.out.println(p);           // "Point(3, 4)"
System.out.println("At: " + p); // "At: Point(3, 4)"
```

Every class inherits `toString()` from the `Object` class. Without overriding it, you'd get something like `Point@1b6d3586` — the memory address. Always override it.

## ArrayList (Dynamic Arrays)

A regular Java array has a **fixed size**. `ArrayList` is a **dynamic, resizable** collection that can grow and shrink.

| Operation | Java ArrayList |
|---|---|
| Create | `new ArrayList<>()` |
| Add | `list.add(item)` |
| Get | `list.get(i)` |
| Remove | `list.remove(i)` |
| Size | `list.size()` |

```java
import java.util.ArrayList;

ArrayList<String> students = new ArrayList<>();
students.add("Alice");
students.add("Bob");
students.add("Charlie");

System.out.println(students.size()); // 3
students.remove(1);                  // remove "Bob"
System.out.println(students);        // [Alice, Charlie]
```
