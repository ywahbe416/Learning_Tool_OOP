# OOP in Java – Part 1

## What is Object-Oriented Programming?

OOP is a programming paradigm that organizes code around **objects** rather than functions and logic. The four pillars are: Encapsulation, Inheritance, Polymorphism, and Abstraction.

Everything in OOP starts with two fundamental concepts: **classes** and **objects**.

---

## Class

A **class** is the blueprint — it defines what attributes (data) and methods (behavior) an object will have. It does not hold data itself; it describes the shape of the data.

```javascript
class Car {
  constructor(make, model, year) {
    this.make = make;
    this.model = model;
    this.year = year;
  }

  describe() {
    return `${this.year} ${this.make} ${this.model}`;
  }
}
```

Think of a class like an architectural blueprint. The blueprint isn't a house — it's the instructions for building one.

---

## Object

An **object** is a specific **instance** created from a class. You can create many objects from the same class, each with its own data.

```javascript
const car1 = new Car("Toyota", "Camry", 2022);
const car2 = new Car("Honda", "Civic", 2023);

console.log(car1.describe()); // "2022 Toyota Camry"
console.log(car2.describe()); // "2023 Honda Civic"
```

`car1` and `car2` are two separate objects — two houses built from the same blueprint.

---

## Constructor

The **constructor** is a special method that runs automatically when you create an object with `new`. Its job is to **initialize** the object's fields with starting values.

```javascript
class Student {
  constructor(name, gpa) {
    this.name = name;   // instance field
    this.gpa = gpa;     // instance field
  }
}

const s = new Student("Alex", 3.8);
console.log(s.name); // "Alex"
```

Key rules:
- In JavaScript, the constructor is always named `constructor`
- In Java, it has the same name as the class
- If you don't define one, a default no-argument constructor is used

## Encapsulation

**Encapsulation** means bundling data (fields) and the methods that operate on that data together inside a class — and **hiding** the internal state from the outside world.

The practice: make fields **private**, expose them only through **public getters and setters**.

```javascript
class BankAccount {
  #balance; // private field (JS syntax)

  constructor(owner, initialBalance) {
    this.owner = owner;
    this.#balance = initialBalance;
  }

  getBalance() {
    return this.#balance;
  }

  deposit(amount) {
    if (amount > 0) this.#balance += amount;
  }

  withdraw(amount) {
    if (amount > this.#balance) throw new Error("Insufficient funds");
    this.#balance -= amount;
  }
}

const acct = new BankAccount("Alice", 500);
acct.deposit(200);
console.log(acct.getBalance()); // 700
// acct.#balance = 99999; // ERROR — private!
```

**Why encapsulate?**
- Protects data from being set to invalid states
- You can change the internal implementation without breaking outside code

In Java: `private` fields + `public` getters/setters is the standard pattern.

## toString()

`toString()` is a special method that returns a **string representation** of an object. It's called automatically when you print an object.

```javascript
class Point {
  constructor(x, y) {
    this.x = x;
    this.y = y;
  }

  toString() {
    return `Point(${this.x}, ${this.y})`;
  }
}

const p = new Point(3, 4);
console.log(String(p)); // "Point(3, 4)"
console.log(`Location: ${p}`); // "Location: Point(3, 4)"
```

In Java, every class inherits `toString()` from the `Object` class. Without overriding it, you'd get something like `Car@1b6d3586` — the memory address. Always override it.

## ArrayList (Dynamic Arrays)

In Java, a regular array has a **fixed size**. `ArrayList` is a **dynamic, resizable** collection that can grow and shrink.

In JavaScript, arrays are already dynamic — they work like Java's `ArrayList` by default.

| Operation | Java ArrayList | JavaScript Array |
|---|---|---|
| Create | `new ArrayList<>()` | `[]` |
| Add | `list.add(item)` | `arr.push(item)` |
| Get | `list.get(i)` | `arr[i]` |
| Remove | `list.remove(i)` | `arr.splice(i, 1)` |
| Size | `list.size()` | `arr.length` |

```javascript
const students = [];
students.push("Alice");
students.push("Bob");
students.push("Charlie");

console.log(students.length); // 3
students.splice(1, 1);        // remove "Bob"
console.log(students);        // ["Alice", "Charlie"]
```
