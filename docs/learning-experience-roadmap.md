# Learning Experience Roadmap

This roadmap turns the DS&A / OOP app from a good interactive site into a stronger teaching tool. The focus is not only prettier interactivity, but better learning transfer, better feedback, and better retention.

## Goal

Help students move through each topic in a tighter sequence:

1. Build a mental model
2. Predict behavior
3. Observe the system in motion
4. Practice the pattern in code
5. Reflect so the idea sticks

## Phase 1: Foundation Scaffolding

Status: implemented

- Add topic prerequisites so students know what knowledge the lesson assumes.
- Add "what to notice" guidance so the visualization has a clear learning target.
- Add common-mistake callouts so misconceptions are surfaced early.
- Add worked examples that show the pattern in a smaller, lower-pressure form.

Why this matters:
- Students often fail challenges because they never formed the right mental model first.
- A strong foundation reduces random trial-and-error in the editor.

## Phase 2: Concept Checks

Status: implemented

- Add short multiple-choice checks before the coding challenge.
- Provide immediate explanations, not just correct/incorrect markers.
- Use concept checks to reinforce the "read -> observe -> explain" part of the lesson flow.

Why this matters:
- Students can appear to follow a demo without actually understanding it.
- Quick checks create a low-cost way to test understanding before coding begins.

## Phase 3: Smarter Coding Feedback

Status: implemented

- Add progressive hint ladders instead of only raw pass/fail output.
- Tie hints to the first failing test or compile state.
- Add reflection prompts after all tests pass so students explain the pattern they just implemented.

Why this matters:
- Pass/fail feedback alone often pushes students into guessing.
- Layered hints preserve challenge while still teaching.

## Phase 4: Retrieval and Review

Status: implemented

- Add revisit prompts for completed topics on the homepage.
- Surface short recall questions so students revisit ideas after completion.
- Use the progress model plus review timestamps as the basis for spaced recommendations.

Why this matters:
- Students remember more when they retrieve concepts after the initial lesson.
- A course should not only move forward; it should also reactivate older knowledge.

Next step:
- Expand beyond the current review intervals into longer-term monthly refresh prompts.

## Phase 5: Future Extensions

Status: not implemented

- Add challenge difficulty ramps: starter, standard, stretch.
- Add topic mastery summaries for instructors or students.
- Add optional "explain your answer" text boxes for deeper metacognition.
- Add analytics on common failures so challenge hints can be refined from real student behavior.

## Product Principles

- Teach one idea at a time.
- Make first actions obvious.
- Turn failures into coaching.
- Prefer prediction over passive viewing.
- Revisit important ideas after completion.
